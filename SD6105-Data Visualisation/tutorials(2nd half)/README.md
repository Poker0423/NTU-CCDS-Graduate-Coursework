## Overview

This repository contains **complete solutions** for the second half of the SD6105 tutorials (Tutorials 5–10): Tableau dashboards, design critique, interaction and animation, D3.js programming, and visualization techniques for high-dimensional, geospatial, time-series, graph and hierarchical data.

Two numbers are used twice by the course (7 and 9), so those tutorials are split into **a** and **b**.

Each tutorial folder contains:

| File | Description |
|---|---|
| `tutorial[N]_solutions.py` | Complete annotated Python script. Written answers are in the docstrings |
| `*.html` | D3.js solutions (Tutorials 5, 7a, 9b) |
| `data/` | Datasets used by the script or page |
| `charts/` | Charts generated by the script (PNG) |
| `screenshots/` | Rendered screenshots of the HTML/D3 solutions |

> ⚠ The handouts give **no data files** for Tutorials 7b, 9a and 10, so those scripts generate **synthetic data** with a fixed random seed, and every such chart is labelled as synthetic. The Tutorial 6.2 redesign is a schematic built on synthetic series. It is not real stock data.

## Tutorial 5 — Tableau: Basics, Maps & Dashboards

### Learning Objectives

- Use the Tableau workspace: **dimensions vs measures**, Columns/Rows shelves, the Marks card
- Build **bar**, **line** (discrete vs continuous dates) and **multiple bar** charts
- Build a **symbol map** with generated latitude/longitude
- Combine sheets into a **dashboard** with **navigation buttons**, **filter actions** and **URL actions**, then publish it to Tableau Public

### Tableau Steps (Sample - Superstore, `Orders` sheet)

| Exercise | Steps in Tableau Desktop |
|---|---|
| Bar chart (Fig 1.12) | Drag `Category` → Columns, `Sales` → Rows (SUM). Drag `Category` → Color. Add fields to Tooltip |
| Line chart (years & months) | `Order Date` → Columns, right-click → **Month (continuous, green pill)**; `Sales` → Rows. For year-vs-year comparison use discrete `MONTH` on Columns + `YEAR(Order Date)` on Color |
| Multiple bar charts | `Region` → Columns, `Category` → Rows, `Sales` → Columns (horizontal bars, one panel per region) |
| Symbol map (Fig 6.1) | Double-click `Country`, `State`, `City` (set geographic roles; build a hierarchy City → State → Country). Tableau adds `Latitude/Longitude (generated)`. Drag `Sales` → Size (and Color) |
| Dashboard (Fig 8.6) | New Dashboard → drag the `Sales`, `symbol-map` and `order-date-sales` sheets (from `Practice- Dashboard-start.twbx`) onto the canvas → add a title "Sales Overview" |
| Practice 1 — Navigation button | Objects → **Navigation** → drag onto dashboard → Edit Button → *Navigate to* another sheet/dashboard, set the image/title and tooltip (Figs 8.7–8.8) |
| Practice 2 — Filter action | Select a view → click the funnel icon **Use as Filter** (Fig 8.9), or *Dashboard → Actions → Add Action → Filter* and choose source/target sheets, *Run on: Select* (Figs 8.11–8.12) |
| Practice 3 — URL action | Objects → **Web Page** (fixed URL). Then *Dashboard → Actions → Add Action → Go to URL* with `https://en.wikipedia.org/wiki/<City>` and target = the web-page object, so the selected city's Wikipedia page appears (Fig 8.16) |
| Publish | *Server → Tableau Public → Save to Tableau Public* (sign in with a Tableau Public account). Run *Optimize* first if prompted |

### Python / D3 Reproduction

The Tableau results are reproduced in `tutorial5_solutions.py` so that they can be viewed on GitHub. The script also generates `dashboard.html`, a D3 dashboard with the same three practices:

| Practice | How it works in `dashboard.html` |
|---|---|
| Navigation button | "Go to Details →" switches to a details view (state table, top cities); "← Back to Overview" returns |
| Filter action | Click a Region × Category bar or a state tile → the other views filter. Click again or use *Clear filters* to reset |
| URL actions | Fixed link (Superstore data page) + **dynamic** Wikipedia link and embedded page for the selected state |

> Offline Python has no geocoder or basemap, so the symbol map is drawn as a **proportional-symbol tile-grid map by state** (circle area ∝ sales). In Tableau, use the city-level map from the steps above.

## Tutorial 6 — Visualization Principles, Interaction & Animation

### Learning Objectives

- Critique charts using **graphical integrity** (zero baseline, Tufte's **Lie Factor**) and the **data-ink ratio**
- Redesign misleading charts (truncated axes, dual axes, mismatched time periods)
- Apply the interaction taxonomy of **Yi et al. (2007)**: Select, Explore, Reconfigure, Encode, Abstract/Elaborate, Filter, Connect
- Distinguish the **congruence** and **apprehension** principles of animation

### 6.1 — GTA Average Home Prices (bar chart)

| Issue | Explanation |
|---|---|
| **Truncated y-axis** | Axis starts at $775K, but bars encode value by length. 2022 looks ~4× 2020 while it is only ~1.5× → **Lie Factor ≈ 7** |
| **Confusing encoding of units sold** | Units sold are written as x-axis labels while the years are inside the bars; the 2nd variable is not visually encoded; no value labels, dense gridlines and a textured background |

**Redesign:** two aligned panels sharing the year axis. Panel 1 shows price bars **from $0** with value and YoY % labels; panel 2 shows units sold as bars (`q1c_redesign_sketch.png`).

### 6.2 — "Tech Stock Throwback?" (dual-axis line chart)

| Issue | Explanation |
|---|---|
| **Dual y-axes with arbitrary, non-zero scales** | Netflix 0–50 vs Tesla 160–360: the overlap is manufactured by the axis choice |
| **Two different periods on one unlabelled x-axis** | Jun 2011–Nov 2013 vs Jan 2019–today, with no dates, which implies a spurious forecast |

**Redesign:** index both series to 100 at their start, plot against "trading days since start" on one shared axis, label lines directly, and add small multiples with real dates (`q2b_redesign_indexed.png`, schematic).

### 6.3 — Compendia (query "TikTok trends worldwide")

| Interaction | In Compendia |
|---|---|
| Select | Click a Thematic Circle; hover a fact dot |
| Explore | Scroll-driven storytelling, animated pan & zoom |
| **Abstract/Elaborate** (most useful) | Thematic Overview → Story View → detailed fact panel (overview first, details on demand) |
| Filter | Relevance slider (number of themes), shared-article slider, fact-dot toggle |
| Connect | Links = shared articles; caption numbers colour-linked to dots |
| Reconfigure / Encode | Limited / not supported (chart types are chosen automatically) |

**Animation:** yes. There are pan-and-zoom transitions and animated highlight updates while scrolling. They preserve context and object constancy, which makes exploration easier. Overly long transitions can slow down expert users.

### 6.4 — Congruence vs. Apprehension

| Case | Principle | Verdict |
|---|---|---|
| (a) group similar transitions + staging | Apprehension | ✅ Followed |
| (b) minimise occlusion | Apprehension | ✅ Followed |
| (c) complex unpredictable curved paths | Apprehension | ❌ Violated |
| (d) bar grows 50 → 80 | Congruence | ✅ Followed |
| (e) sorted bars keep their identity | Congruence | ✅ Followed |
| (f) points morph into bars with no shared dimension | Congruence | ❌ Violated |
| (g) sales → profit animated like a time step | Congruence | ❌ Violated |

## Tutorial 7a — D3.js Briefing

### Learning Objectives

- Understand **data-driven documents**: selections, method chaining, data binding (`data()`, `enter()`, `append()`)
- Use **scales**, **axes**, **legends**, **events** and **transitions**, and load CSV files

### Answers

| Question | Answer |
|---|---|
| One line in the console (Demo 3) to set every circle's radius to 20 px | `d3.selectAll("circle").attr("r", 20)` → `screenshots/ex3_console_radius20.png` |
| Can `d3.selectAll('circle').datum()` trace the data in Demo 3 and Demo 4? | **Demo 3: no.** Circles are appended in a `for` loop without binding, so `datum()` returns `undefined`. **Demo 4: yes.** `data()` stores each object in the element's `__data__`; `datum()` returns the first circle's passenger object, and `d3.selectAll('circle').data()` returns all 5 |
| Main difference between Demo 4 and Demo 3 | Demo 3 is **imperative**: a loop with hard-coded indexing of `sampleData[i]`. Demo 4 is **declarative data binding**: `selectAll().data().enter().append()` creates one element per datum, and attributes are functions of `(d, i)`, which enables later update/exit and transitions |
| Change circle attributes | `solutions/ex4c_attribute_experiments.html`: fill-opacity, r, stroke-width, cx, cy |
| Draw rectangles instead of circles | `solutions/ex4b_rectangles.html`: `rect` uses top-left `x, y` + `width/height` (shift by size/2 to keep the same centres) |
| Scale experiments: non-zero stroke, change scales, radius ∝ fare | `solutions/ex5_scales_experiments.html`: radius via `d3.scaleSqrt` (area ∝ fare) |

> **Bug found in `6-scales2.html`:** the stroke scale's domain is `["0","1"]` (strings) but `d.survived` is a number. `d3.scaleOrdinal` matches keys with `===`, so the numbers are appended to the domain implicitly and survivors get the **red** stroke (the reverse of the intent). It only becomes visible once `stroke-width > 0`. Fix: `s(String(d.survived))`.

## Tutorial 7b — High-Dimensional Data Visualization

### Learning Objectives

- Choose techniques for **multivariate numerical** data: parallel coordinates, scatter-plot matrix, dimensionality reduction (PCA)
- Visualize relationships among **categorical** variables: **parallel sets**, faceted heatmaps
- Compare individual records with **glyphs** (radar/star charts, Chernoff faces)

### Design Summary

| Task | Main design | Why |
|---|---|---|
| (a) Clusters / patterns across 6 numerical attributes | **Parallel coordinates** coloured by k-means cluster (+ SPLOM + PCA biplot) | All dimensions at once; clusters = bundles of lines; axis order and alpha manage clutter |
| (b) Gender × Region × Category | **Parallel sets** (+ Region × Category heatmaps faceted by gender) | Designed for categorical data: box width = frequency, ribbons = joint counts |
| (c) Compare individual customers | **Radar-chart glyphs** (small multiples + overlay, population median as reference) | One shape per customer; profiles compared at a glance on normalised axes |

## Tutorial 8 — Geospatial Data Visualization

### 8.1 — Which map?

| Data | Type | Visualization |
|---|---|---|
| (a) Annual sales of each McDonald's in Singapore | Point data + weight | **Proportional symbol map** (circle area ∝ sales); density/hexbin map if overplotted |
| (b) Average temperature of EU countries | Region data, intensive value | **Choropleth**, sequential palette (diverging if the message is deviation from the mean) |
| (c) Population aged 65+ by US state | Region data | **Choropleth of the 65+ share**; for absolute counts use a **cartogram** / proportional symbols (avoids large-area bias) |

### 8.2 — Which projection? (latitude rule)

| Location | Projection | Reason |
|---|---|---|
| (a) Malaysia | **Cylindrical** (Mercator) | Equatorial; least distortion where the cylinder touches |
| (b) China | **Conic** (Albers equal-area) | Mid-latitude, wide east–west extent |
| (c) India | **Cylindrical** (conic also acceptable) | Mostly tropical/low latitude |
| (d) USA | **Conic** (Albers, std. parallels 29.5°N / 45.5°N) | Classic mid-latitude case |
| (e) North Pole | **Azimuthal** (equidistant / polar stereographic) | Plane tangent at the pole |

`charts/q2_projection_distortion.png` shows equal-size circles distorted by each projection family (pure numpy).

## Tutorial 9a — Time-Series Data Visualization

| Scenario | Design | Justification |
|---|---|---|
| (a) Music trends: 4 genres, daily, 5 years | **Streamgraph** (ThemeRiver) + 100% stacked area | Stream thickness = popularity over time; stacking shows proportions; the organic shape shows the overall "flow" |
| (b) CPU of 100 servers, per minute, 30 days | **Horizon graphs** ordered by similarity + heatmap overview | Layered bands make spikes dark and salient in very short rows; 100 series fit on one screen; aligned rows reveal similar servers and fleet-wide incidents |
| (c) Hourly website traffic for 1 year | **Calendar heatmap** + weekday × hour heatmap | One cell per date; weekdays in rows show the weekend effect; month blocks compare months |

## Tutorial 10 — Graph, Tree & Dashboard Design

### 10.1 — Dense graph (100 nodes): **adjacency matrix**

- No edge crossings or occlusion at any density; every node pair has its own cell. Edge lookup, cluster (block) detection and degree comparison are easy.
- **Limitations:** depends heavily on row/column **ordering** (needs seriation or community ordering); path-following tasks are hard; less intuitive; uses n² space. Hybrids such as NodeTrix address some of these.

### 10.2 — University hierarchy

| Task | Technique |
|---|---|
| Hierarchical relationships between units | **Node-link** tree diagram |
| Compare research funding across departments/colleges | **Treemap** (area = funding) |
| Overview of units across hierarchy levels | **Sunburst** (rings = levels) |

**Treemap vs node-link (large hierarchy):** the treemap is space-filling, scalable, and encodes size and part-whole. However, its structure is implicit, depth and paths are hard to read, area is judged less accurately, and small nodes become unreadable.

### 10.3 — Dashboard problems

Doesn't fit on one screen · the navigation icon bar takes the most prominent space · too many filters · bright, inconsistent colours on a busy photo background · stacked horizontal bars for a time trend · map dots with truncated labels instead of encoded values · narrow-range QA chart with occlusion · tiny low-contrast truncated text · no targets or context · weak grouping of filters and their charts.

### Output Charts

| Chart | Content |
|---|---|
| `q1_nodelink_vs_matrix.png` | Hairball vs matrix in random order vs matrix reordered by community |
| `q2_nodelink_tree.png` | University → College → School → Department |
| `q2_treemap_funding.png` | Squarified treemap (own implementation) of funding |
| `q2_sunburst_levels.png` | Units per hierarchy level |
